My specialty

Evals first.

An AI feature gives a different answer every time you ask. So "does it work?" isn't a yes or no, it's a score. I build the eval that produces that score, and I treat it as the spec: if it doesn't pass, it doesn't ship.

1 · Golden set dataset

The inputs that matter

Real cases from real usage, deliberately seeded with the edge cases and past failures that hurt users. Each one labelled with what a good answer looks like.

2 · Rubric rule

"Good", written down

Criteria specific enough that two reviewers grade the same output the same way. It's the acceptance criteria of AI features, and the PM writes it.

3 · Grader balance

A score you can gate on

Code checks first, an LLM judge for the fuzzy criteria, people where nuance matters. Every automated grader is checked against human labels before I trust it.

How I build a golden set

Six steps, from "it feels better" to a number

Full guide →
  1. 01Start from the decision. What the feature decides, for whom, and which mistakes are fatal versus annoying.
  2. 02Pull from reality. Sample real inputs across the segments you serve, not the prompts you wrote yourself.
  3. 03Seed the ugly cases. Edge cases, adversarial inputs and every failure a user has already reported.
  4. 04Label by hand, twice. Two reviewers, one rubric. Where they disagree, the rubric gets fixed, not the score.
  5. 05Hold some back. Keep a split you never tune prompts on, so a higher score means better, not memorised.
  6. 06Gate and grow. A regression blocks the release, and every production failure becomes a new case.

Store Data Engine

Problem: A market benchmark like "median leather bag €640" is meaningless, and labelling 697K products by hand would cost thousands.

Process: A solo-built pipeline: scrape 397 Shopify stores, enrich ~110K products with an LLM via the Batch API, then propagate labels to lookalikes for free.

Eval: Propagation rules scored on a held-out split before touching a row, and a 50-row hand audit against source text that put the LLM at ~94% precision and keyword rules at ~21% error.

Proof: 697,299 products for ~$31 of LLM spend, +72K free labels at 97.1% held-out precision, and benchmarks split into real tiers (mid €82 / premium €197 / luxury €440).

What are AI evals, and why does Ali focus on them? expand_more

An eval is a repeatable test of an AI feature's quality: a golden set of real inputs, a rubric that defines a good answer, and a grader (code checks, an LLM judge, or people) that turns outputs into a score. AI features are probabilistic, so that score replaces the pass/fail acceptance test. Ali treats the eval as the spec: a regression blocks the release. Read the evals guide.

How do you build a golden set for an AI feature? expand_more

Start from the decision the feature makes and which mistakes are fatal. Sample real inputs across the segments you serve, seed the edge cases and every reported failure, label each case by hand with two reviewers against one rubric, hold back a split you never tune prompts on, then gate releases on the score and add every production failure as a new case. The step-by-step guide has a worked example.
